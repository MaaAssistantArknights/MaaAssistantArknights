# データ更新

::: info UI 専用機能
本ページの機能は UI 層で実装されています。詳細は[始めに](../newbie.md#このドキュメントについて)を参照してください。
:::

データ更新タスクは、**オペレーター名簿と倉庫在庫**のキャッシュデータを同期し、[在庫維持](./depot-maintain.md) などの機能に正確な在庫ベースラインを提供します。

## 機能説明

本タスクには以下の 2 つのサブ項目が含まれ、個別にチェックできます：

### オペレーター認識

- 所持・未所持のオペレーター名簿を認識し、潜在データを保存します。
- 認識結果は [公募認識](./tools.md#公募認識) でオペレーターの潜在を表示するために使用されます。
- 認識完了後に前回の同期時間が表示されます。
- `設定 - サードパーティ` の `オペレーターをYituliuから取得` を有効にすると、本サブ項目はタスク開始時にYituliuの育成データを直接読み取り、エミュレーターでの認識を行いません。

### 倉庫認識

- ゲーム内の倉庫在庫を認識し、材料数量のキャッシュを更新します。
- 認識結果は [在庫維持](./depot-maintain.md) タスクの不足計算に使用されます。
- [小ツール - 倉庫アイテム認識](./tools.md#倉庫アイテム認識) と同じデータを共有します。認識完了後に前回の同期時間が表示されます。
- 倉庫全体の認識に成功した場合のみ、在庫キャッシュが有効に戻り同期時刻が更新されます。部分的な認識、失敗、中止では復旧しません。オペレーター育成で素材を消費する可能性がある場合、キャッシュは自動的に無効となり、この状態は再起動後も保持されます。

::: tip
本タスクと [小ツール - 倉庫アイテム認識](./tools.md#倉庫アイテム認識) の違い：小ツール版は倉庫画面への手動移動が必要ですが、本タスクは自動的に倉庫画面に移動して認識を完了し、トリガー間隔と組み合わせて自動化できます。
:::

## トリガー間隔

タスクの実行頻度を設定できます：

| 選択肢 | 説明                                                                  |
| :----- | :-------------------------------------------------------------------- |
| 毎回   | タスクキュー実行のたびに更新を実行します。                            |
| 毎日   | 1 日に最大 1 回実行。当日の再度のトリガー時は自動的にスキップします。 |
| 毎週   | 1 週間に最大 1 回実行します。                                         |

「毎日」に設定することを推奨します。毎日初回実行時にデータを自動同期し、頻繁な OCR による効率低下を回避できます。

在庫キャッシュが無効とされている場合、有効にした倉庫認識は「毎日」「毎週」の間隔にかかわらず、次回の本タスク実行時に再度行われます。
