# 材料合成

`MaterialCraft` 使用加工站材料配方和制造站双芯片配方，先展开依赖，再按顺序合成。`items` 表示需要新合成的数量，不是目标库存总量。

启动时若已在加工界面或配方列表，直接继续；若在加工站房间，点击左下角加工入口。其他页面通过 `MaterialCraft@InfrastBegin` 复用基建导航，确认已到基建后立即结束导航，不点击铃铛、不领取产出，也不执行领取前的固定等待。随后通过加工站的正常/缩小视图模板定位设施，当前视图找不到时使用与办公室任务相同的横滑流程。确认进入加工站房间后才点击加工入口；进入后未确认页面的重试会先返回基建。

```json
{
    "items": [{ "itemId": "30135", "count": 1 }],
    "inventory": { "30124": 2, "30134": 1, "4001": 10000 }
}
```

`inventory` 是调用方提供的库存快照。数量为非负整数，目标数量必须大于零。兼容 `items` 字典、`targets` 数组、单个 `itemId` / `count` 和 `depot` 库存字段；新调用方建议使用上面的格式。

## 只计算计划

```cpp
AsstSize AsstGetMaterialCraftPlan(const char* params, char* buff, AsstSize buff_size);
```

先调用 `AsstLoadResource`。此接口不需要创建实例或连接游戏，不会启动任务、点击游戏或修改库存。

返回 UTF-8 JSON 的字节数，不包含结尾 NUL。`buff` 为 null 或容量不足时不写入缓冲区，可按返回大小分配后重试。资源未初始化或参数无法解析时返回 `AsstGetNullSize()`。两次调用之间允许资源更新，调用方应再次检查返回长度。

计划包含：

- `valid` / `error`：是否能构造计划及失败原因。循环依赖、未知目标和数量溢出不能执行。
- `operations`：有序的 `formula_id`、`facility`（`Processing` 或 `Mfg`）、`item_id`、`batches` 和产出 `count`。
- `inventory`：执行完整计划后的估算库存。
- `missing`：缺少的基础材料，包含 `item_id` 和 `count`。
- `gold_cost` / `ap_cost`：64 位整数成本；`mood_cost` 为 `ap_cost / 360000`。

`valid: true` 与 `missing` 非空可以同时出现，保留了根据旧库存快照尝试加工的能力。它不保证游戏内材料充足。规划不计干员副产品；只有输入库存包含 `4001` 时才计算龙门币的库存变化。

## 执行回调

以下均为 `SubTaskExtraInfo`，以外层 `taskid` 关联执行，不能用当前正在编辑的队列代替已提交快照。

- `MaterialCraftPlan`：`details` 与只计算计划的结果相同。
- `MaterialCraftPlanFailed`：计划无效或存在缺料，`details` 包含具体原因。
- `MaterialCraftOperationStarted`：已读回加工份数、即将开始加工。`details` 包含从 0 递增的 `operation_id`、`item_id` 和实际选中的 `batches`。
- `MaterialCraftOperationCompleted`：已识别到领取界面，包含相同操作标识及 `inventory_changes` 数组；数组元素为 `item_id` 和有符号数量 `count`。`inventory_complete: false` 表示无法排除副产品，变化只能作为已知部分。

游戏限制单次份数时，一个计划操作可以拆成多个执行回调。调用方必须按 `(taskid, operation_id)` 去重。完成回调可能早于领取界面的关闭；之后停止任务也不能撤销已经确认的库存变化。

中断时保留已确认的库存变化。开始后未收到完成回调，或库存变化不完整时，保留库存待确认标记，但不拦截下一次合成，允许使用当前库存快照继续规划。每种目标材料的全部计划批次确认完成后，即从待合成区移除；整轮结束时统一显示已确认的库存净变化。回调异步传递，调用方应在 `AsstStart` 前持久化库存待确认状态，覆盖进程意外退出的情况。

## 加工站进驻与换人

`station_operators` 为可选布尔参数，默认 `false`。界面以“进驻干员”勾选开关替代“计算合成”按钮，并保存选择；开始加工时仍自动检查合成计划。只有勾选后才启用下面的干员扫描、评分、心情限量和换人流程。关闭时沿用原先直接选择配方、设置份数并加工的逻辑，不操作进驻干员。副产物识别与库存增量回调在两种模式下均保留，制造站双芯片流程不受此开关影响。

每批加工前先选择配方，并检查左侧进驻干员的剩余心情。空位、心情为 `0` 或不足以完成一份当前配方时，点击左侧卡片进入干员列表，复用基建干员识别、技能排序、翻页和进驻确认；确认前复核目标头像及唯一选中状态，确认后检查已返回加工页，并直接核对保留的配方及单份数量，不重新打开配方列表。

若进入下一步时，当前页已因心情不足显示超负荷提示，则先按下一配方的缓存评分直接更换干员，再选择配方。提示遮挡配方槽时，使用仍可见的加工按钮与份数控件确认加工页，避免误报页面识别失败；不会执行超负荷加工。

技巧概要（`3302`、`3303`）与精英材料复用制造站、贸易站的当前技能图标识别，并以实际识别到的技能 ID 评分；不会根据干员名字补全精二技能。支持通用概率加成、技巧概要专属概率加成，以及羽毛笔、伯塔尼、蒂比的卷3心情减免。升级前后技能不叠加，心情返还不增加概率分数。九色鹿、芳汀、白铁、霜华不参与加工站选人；仅对精英材料、基建材料或芯片有效的技能不产生技巧概要分数。

同一合成队列仅在首次加工时完整扫描干员，缓存所有加工站技能候选（包含只对后续配方有效的技能）、身份和可用状态。后续换材料、换人直接按缓存重新计算，按副产品概率降序、单次心情消耗升序选择，二者相同时保留当前干员。当前干员仍最优时不进入进驻列表；需要换人时仅翻页定位目标头像并复核技能。已有干员即使有心情也参与重新比较；不选择正在其他设施工作的干员。每次准备加工时将加工页读到的精确心情回写对应缓存；已知心情不足一份的干员不再重复尝试，同一配方后续批次复用已验证的进驻结果。缓存仅在本队列生效，下一队列重新扫描。返回加工页后，单份实际消耗必须与识别技能算出的消耗一致才允许加工。

评分器支持凯瑟琳的白铁宿舍联动输入。现有通用图标识别只确认工作状态，尚未识别休息状态，因此无法确认白铁在宿舍时暂用50%的已知概率增幅下限，并在日志中标记。棘刺的心情返还通过每批结束后重新读取实际心情处理，不预支返还心情。

精英材料评分读取 `material_recipes.json` 的 `buffType: W_EVOLVE`，原始心情为 `apCost / 360000`，资源更新器同步保留该类别。支持：

- 固定加成：通用40%～80%、精英材料70%～100%，以及瑕光、矩的复合技能；休谟斯仅在原始心情为2时额外加40%，罗小黑仅在原始心情为8时加50%。
- 材料特化：源岩、装置、聚酸酯、异铁、酮凝集、晶体，以及号角仅对炽合金块的100%加成。熔泉与折桠共用异铁图标：折桠只对异铁组生效，无法确认身份时也只计算二者共同支持的异铁组。
- 心情修正：固定消耗、增加消耗、按原始消耗门槛减免，以及晶体/异铁组专属减免。条件始终按原始配方判断，升级技能不重复叠加。年仍按概率优先参与排序；号角加工炽合金块时与年同为100%加成，但以3点心情优于年的6点。

概率按 `10% × (1 + 加成百分比 / 100)` 计算，例如100%加成对应20%实际概率。副产品品种固定、龙门币减免不额外加分；宿舍人数、情报、因果/业报等动态收益暂不计算。候选实际心情不足时继续寻找其他干员，同一次准备中不重复尝试已排除的头像；无可用候选或进驻失败时停止加工。

心情上限为 `24`。单批份数根据游戏显示的剩余心情及一份配方的实际心情消耗计算，包含干员技能对消耗的修正；点击开始前再次读取本批总消耗并确认可负担。每批领取完成后重新检查，不依赖本地扣减来推测剩余心情。心情耗尽且仍有待加工材料时换人；剩余心情不足一份时也会提前换人。实际消耗为 `0` 时仍要求干员心情大于 `0`。

进驻或心情检查失败时发送 `MaterialCraftOperatorFailed`，`details.reason` 为 `MaterialsUnavailable`（当前材料不足，可加工份数为零）、`MoodRecognitionFailed`（心情、消耗或单份数量无法确认）、`OperatorSelectionFailed`（无法完成可用干员进驻）、`SkillVerificationFailed`（实际心情消耗与识别技能不一致）、`FormulaVerificationFailed`（换人后配方未通过核对）或 `MoodVerificationFailed`（开始前总消耗复核失败），并在 `debug/material_craft/operator_failed` 保存截图。用户停止时不发送该失败事件。

### 副产物与库存

从点击开始加工后即保留等待结果页期间的右侧画面，因为副产物弹窗可能早于主产物的领取标记出现。这些画面与领取页后的连续截图一起参与识别，不会因先等待领取标记而丢弃早到的弹窗。

名称区域保留完整首字；原图识别不足时，将蓝通道放大三倍复核，并按资源中已确认的完整名称纠错规则处理。少于十份加工时，数量仅需一个数位，使用较窄区域排除左侧图标纹理；置信度不足时，用 RGB 三通道的最小值抑制彩色高光，再读取白色数字。复核仍要求原有置信度门槛与两帧一致，不因图标干扰放宽确认条件。

技巧概要的副产物名称可能分成两行；分别确认“技巧概要”和下一行的卷数后，合并为完整名称，同时调整数量区域的位置。副产物与主产物同名时，数量合并到同一条库存增量。

点击开始加工后立即轮询领取界面；首次确认领取页时，先缓存右上角副产物弹窗的连续截图，再做 OCR 和发送完成回调，避免 OCR 与回调耗时阻塞瞬时弹窗捕获。识别要求弹窗标题匹配、材料名称与物品表完全一致、数量在当前加工批次数范围内，并至少两帧一致。

`MaterialCraftOperationCompleted.details.byproducts` 列出已确认的副产物，它们同时合并到 `inventory_changes`，由现有界面逻辑按 `(taskid, operation_id)` 去重并更新库存；副产物与消耗原料同名时先合并净变化。多帧中重复出现的弹窗不累加，同一材料取已确认的最大数量。新批次会清空上批记录。

截图丢帧或同种副产物分多次通知时，可能只能确认部分数量，因此加工站仍保留 `inventory_complete: false`。未读到弹窗不能证明没有副产物，也不能据此把库存标记为完整；识别到的部分会正常入账，剩余差异需要重新识别仓库。绿字显示的是额外概率，不能把其为 `0%` 解释成没有副产物。

## 制造站双芯片

支持 `3213` 至 `3283` 对应的八种职业双芯片，界面分类为“芯片组（制造站）”。每份消耗两个对应职业的芯片组及一个 `32001` 芯片助剂，不计加工站心情与龙门币成本。配方使用 `Mfg@` 前缀，避免制造站与加工站的数字配方 ID 冲突。芯片组不足时列为缺料，不自动转换其他职业的芯片组。

执行时寻找三级制造站，记录当前产品、配方原料及生产份数；已有产出先领取，并通过同一套开始/完成回调更新库存。原配方为源石碎片时，通过原料区分固源岩和装置两种配方。正在制造双芯片的设施会被跳过，以保留其已有订单。全程不更换干员，不使用无人机。

优先使用生产作战记录或赤金的三级制造站，遇到源石碎片站时继续检查其他制造站。只有确认所有制造站均生产源石碎片时，才回到其中一个三级站制造双芯片；无法识别的制造站不视为源石碎片站。检查期间不领取或修改被跳过站的订单，最终选定站后重新读取原配方和数量。

从需求页面进入基建后，先确认地图已滑到左侧且设施位置稳定，再统计制造站。进入设施时点击名称色条旁的房间内部，避免地图偏移造成漏查或点击色条无法进入。

`replenish` 为可选布尔参数，默认 `false`，含义与基建任务的源石碎片自动补货一致。WPF 从当前配置的首个基建换班任务读取“源石碎片自动补货”设置，不依赖当前打开的任务设置页；没有基建配置时传入 `false`。原配方为源石碎片且该设置开启时，制造双芯片后恢复同一原料配方，直接点击最大并确认数量为 `99`；未开启时严格恢复切换前记录的生产数量，包括 `0`。其他原配方始终恢复原数量。

双芯片列表先匹配图标，再读取同一卡片的完整产品名称；不符合目标名称的候选被过滤。先检查当前页，只有找不到目标时才朝目标所在的上半部或下半部滑动一次，不预先回顶。八个职业共四行，一页显示三行；作战记录、赤金、源石碎片分类均在当前页查找，不额外滑动。列表识别区域覆盖滑到底部后的最后一行。选择目标后再次核对图标与产品名称，读回生产份数后在提交前复核，才确认更换。

双芯片列表图标阈值为 `0.80`，详情图标阈值为 `0.85`；名称必须与目标完全一致，且 OCR 置信度不低于 `0.90`。列表名称与详情名称的像素预处理下界分别为 `120`、`160`。职业图标的正确匹配与错误匹配分数存在重叠，不能单独用图标阈值确认职业。这些参数根据国服 1280×720 截图及缩放、压缩、变暗、模糊样本校准；其他客户端或显示条件仍需独立验证。

“已完成”横条会遮挡产物图标，因此提交后的完成检查和领取检查允许使用完整名称加完成标记确认产品，完成标记阈值为 `0.90`；选择配方及提交前仍要求图标通过。领取动画可能暂时遮挡页面，程序仅点击一次领取，然后有界等待页面稳定并确认仓库归零。恢复配方时，作战记录分类同时支持选中与未选中两种外观。

单批数量受制造站仓库容量约束，超出时分批执行。仅当生产份数归零、仓库占用等于本批双芯片数量乘以五，且领取后仓库归零时，才发送完成回调。结束时按上述补货设置恢复原配方及份数并复核；游戏本身因更换配方重置的生产进度无法恢复。

原配方写入用户目录的 `debug/material_craft/manufacturing_restore_<taskid>.json`，其中 `original_batches` 保留切换前数量，`batches` 为计划恢复数量，确认恢复后删除。停止、连接中断或完成状态不明确时，不继续点击或取消可能未完成的订单；保留恢复记录和截图，并通过 `MaterialCraftManufacturingRestoreRequired` 提示手动检查。该事件的 `details` 包含 `item_id`、`ingredient_id`、`batches`、从零开始的设施 `index` 和 `reason`。常规失败使用 `MaterialCraftManufacturingFailed`。中断后的库存仍遵循上面的待确认规则。

## 材料需求识别

`MaterialRequirement` 识别当前精二或专精材料需求界面，不自动进入合成设施。缺少普通材料或双芯片时会点击图标查看名称，并关闭说明弹窗；识别结果进入待合成列表，点击开始合成后才导航到设施。未确认页面类型时按识别失败处理，避免说明弹窗覆盖需求时误报材料已足够。`MaterialRequirementInfo` 的 `details` 包含 `done`、`status` 和 `items`。

精二页面通过“精英阶段 2”标记确认，并读取普通材料左侧的芯片数量栏。五星、六星分别支持 `3`、`4` 个双芯片的需求；库存足够时不打开说明弹窗，缺少时只添加 `required - owned` 个。四星使用的其他芯片不会当作双芯片。缺料但数量无法确认时标记为部分识别，不能显示材料已足够。

普通材料优先通过点击图标、读取说明弹窗名称识别，避免逐个匹配全部材料及多种图标尺寸。只对缺料项打开弹窗；库存足够时直接跳过。专精左侧的技巧概要仍使用已知单个模板确认，无需遍历材料或额外打开弹窗。

名称检测只接受深色标题标签中的完整材料名，置信度不足时对单行标题重新进行 OCR。名称必须与当前资源中可合成材料的名称完全一致，置信度不低于 `0.95`，且连续两次一致。普通材料名称不能映射为双芯片或技巧概要；双芯片仍仅接受对应八个职业的完整名称。点击限制在图标中央，避免随机点击落到数量条。也支持从已打开的材料或双芯片说明弹窗启动识别；会先关闭弹窗，再读取完整需求。

每次关闭弹窗后确认仍在原类型的需求页面，全部弹窗关闭后统一重新读取一次数量，不重复扫描材料图标。普通材料弹窗没有读到稳定名称时，仅对该缺料项回退到原有图标识别；已读取但类别不符的名称直接拒绝。双芯片不使用图标猜测职业。数量发生变化、名称仍无法确认或数量无法读取时保留其他已确认项并提示部分识别；弹窗无法关闭或切换到另一类页面时按失败处理。停止后不继续点击。

同时缺少双芯片与普通材料时，两者进入同一待合成列表，芯片项位于本次识别结果的前面。执行器按计划顺序处理，制造站领取双芯片并恢复原配方后，再进入加工站合成普通材料及其前置材料；手动调整项目顺序时也支持先加工后制造。任一步骤失败或停止时，不继续执行后续项目，已确认的产出按执行回调更新库存。

数量识别使用字符模型，仅接受完整的 `已有数量/需求数量`。优先识别原尺寸预处理结果与三倍放大的原色区域；置信度不足时，再通过红色通道去除蓝底，复核原尺寸和两倍放大的数字。必须获得两次置信度均不低于 0.95 的一致结果；高置信度结果冲突、格式异常、数量溢出或复核不足时，该项按识别失败处理，不推测缺口。部分识别失败也会在 `debug/material_requirement` 保存截图。

`status` 为 `success`、`partial` 或 `failed`。`items` 只包含缺料项：`item_id`、`item_name`、`owned`、`required`、`shortage`。`success` 且数组为空时显示“材料已足够”；不能把 `partial` 或 `failed` 的空数组当作没有缺料。

从训练室专精确认页启动合成时，依次返回专精技能选择页、训练室、基建总览，共点击三次左上角返回，随后复用基建导航。该返回分支不适用于其他需求页面。
