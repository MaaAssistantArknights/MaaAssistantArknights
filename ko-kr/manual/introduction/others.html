UI 전용 기능

이 페이지의 대부분 기능은 UI 계층에서 구현됩니다. 자세한 내용은 초보자 가이드를 참고하세요.

GPU 가속 추론

DirectML을 사용하여 GPU를 호출하여 인식 추론을 가속화합니다PR. 적은 GPU 사용량으로 CPU 사용량을 크게 줄일 수 있으므로 활성화하는 것을 권장합니다.

테스트 결과, 일부 그래픽 카드는 기능 부족이나 성능 저하로 인해 이 기능을 사용할 때 인식 문제가 발생할 수 있습니다. MAA에는 이미 일부 GPU 블랙리스트가 내장되어 있습니다PR1PR2. 목록에 없는 그래픽 카드에서 이 기능을 활성화한 후 인식 문제가 발생하면 Issue를 제출해 주세요.

한 번만

메인 인터페이스와 설정의 구성 변경은 일반적으로 자동으로 저장되지만 다음은 MAA 재시작 후 재설정됩니다.

  • * 표시가 있는 옵션
  • （한 번만） 표시가 있는 옵션
  • 체크박스를 우클릭하여 얻은 반선택 상태

많은 체크박스는 우클릭으로 반선택(한 번만 적용, MAA 재시작 후 리셋)할 수 있습니다. 주요 적용 사례:

  • 메인 작업 목록: 작업을 우클릭하여 반선택하면 이번에만 실행되고 재시작 후 원래대로 돌아갑니다. 기본 우클릭은 「한 번만 적용」이며, 설정 - UI 설정 - 메인 작업 오른쪽 클릭 효과 반전에서 「한 번만 건너뛰기」(반선택한 작업을 이번에만 건너뜀)로 전환할 수 있습니다.
  • 전투 설정: 이성 회복제 사용, 순오리지늄 사용 등의 옵션은 우클릭 반선택 시 이번에만 적용됩니다.

시작 시 자동으로 구성 변경

MAA는 시작 매개변수를 통해 구성을 자동으로 전환할 수 있습니다. MAA 프로세스 이름 뒤에 --config <구성 이름>을 추가하면 됩니다. 예: ./MAA/MAA.exe --config Official

일부 기호는 이스케이프해야 합니다. JSON 참조하세요. 예를 들어 구성 이름이 "Official"인 경우 매개변수는 --config \"Official\"가 되어야 합니다

시작 전/후 스크립트

v4.13.0 이후에는 시작 전/후 스크립트를 설정할 수 있으며, 작업 전후에 배치 파일을 자동으로 실행할 수 있습니다.

배치 파일인 *.bat 파일의 경로를 입력해야 합니다.

구성 마이그레이션

Windows 버전에서는 MAA의 모든 구성이 config 폴더에 저장됩니다. 이 폴더를 마이그레이션하면 모든 MAA 설정이 이전됩니다.

정기 실행

설정 - 정기 실행에서 최대 8개의 예약 작업을 설정할 수 있습니다. 각 항목에는 활성화 토글, 시간(시:분), 해당 구성이 포함됩니다.

  • 예약 시간에 도달하면 MAA가 자동으로 에뮬레이터에 연결하여 현재 구성에서 체크된 작업을 실행합니다.
  • 각 예약 항목의 체크박스는 우클릭 반선택(한 번만)을 지원하며, 이번에만 적용되고 MAA 재시작 후 리셋됩니다.

강제 예약 시작

체크하면 현재 실행 중인 작업을 중지하고, 게임을 재시작하여 새 작업을 시작합니다. 게임의 매일 04:00(서버 현지 시간) 플래시 업데이트 대응에 적합합니다——플래시 업데이트 후 게임을 강제로 재시작하고 작업을 재실행하여 작업이 멈추는 것을 방지합니다.

플래시 업데이트 후 자동으로 재연결하여 작업을 계속하려면 시작 작업도 함께 활성화하세요.

커스텀 구성 선택

체크하면 각 예약 항목에 서로 다른 구성을 지정할 수 있습니다. MAA는 예약 트리거 2분 전에 재시작하여 해당 구성으로 전환한 후 작업을 실행합니다.

업데이트

MAA의 업데이트는 두 가지 콘텐츠로 나뉩니다:

  • 소프트웨어 버전: 메인 프로그램의 인터페이스 및 기능 업데이트.
  • 리소스 버전: 소재 데이터 업데이트. 새로운 스테이지 맵, 드롭 아이콘, 공개 채용 오퍼레이터 태그 등이 포함됩니다. 소프트웨어 버전 출시 시 일반적으로 당시 최신 리소스가 포함되어 있습니다.

내비게이션 핫업데이트

또 다른 「내비게이션 핫업데이트」가 있으며, 자동으로 트리거되어 메인 인터페이스의 알림과 이벤트 스테이지 입구를 업데이트합니다. 성공 후 우측 상단에 알림이 표시됩니다.

업데이트 채널

설정 - 업데이트 설정에서 업데이트 채널을 전환할 수 있습니다:

  • 정식 버전: 버그가 적고, 새로운 기능과 테마 지원이 느립니다. 새로운 기능 지원까지 수주가 걸릴 수 있습니다.
  • 공개 베타 버전: 약간의 버그가 있을 수 있지만, 새로운 기능과 테마 지원이 빠릅니다.
  • 내부 테스트 버전: 불안정한 기능을 포함하며, 테스트 전용입니다. 다른 곳에서 내부 테스트 버전에 대해 논의하지 마세요.

팁

인터페이스에 버전이 너무 낮다고 표시되고 최소 요구 버전이 공개 베타 버전이지만, 최신 버전으로 감지된 경우 해당 기능은 현재 공개 베타 버전에서만 제공됨을 의미합니다. 정식 버전 출시를 기다리거나 공개 베타 버전으로 전환하여 받으세요.

자동 업데이트

설정 - 업데이트 설정에서 업데이트 소스를 선택할 수 있습니다:

업데이트 소스설명
해외 소스(GitHub)소프트웨어 버전은 GitHub에서 가져옵니다. 리소스 버전은 MirrorChyan이 무료 업데이트 감지를 제공하며, 수동으로 리소스 업데이트를 클릭하여 GitHub에서 다운로드할 수 있습니다.
MirrorChyanCDK를 입력하면 소프트웨어와 리소스의 자동 업데이트를 지원하며, 고속 CDN에서 우선적으로 다운로드합니다. 더 안정적이고 빠릅니다.

업데이트 설정에서 다음 옵션을 켜거나 끌 수 있습니다:

  • 시작 시 업데이트 확인
  • 정기 업데이트 확인(서버 현지 시간 04:00 / 22:00. 게임 내 매일 리셋 시간과 이성 완전 회복 시간에 해당)
  • 업데이트 패키지 자동 다운로드: 끄면 알림만 표시되며, 직접 업데이트 패키지를 다운로드하여 MAA에 드래그하여 업데이트할 수 있습니다(아래 수동 업데이트 참조).
  • 업데이트 패키지 자동 설치

작업 실행 중에 리소스 업데이트가 감지된 경우, 시스템이 유휴 상태일 때 자동으로 로드되어 다음 작업부터 적용됩니다.

수동 업데이트

자동 다운로드가 실패하거나 네트워크가 불량한 경우, 수동으로 업데이트 패키지를 다운로드한 후 .zip 압축 패키지를 MAA 메인 창에 직접 드래그하여 업데이트를 완료할 수 있습니다. MAA는 패키지 유형을 식별하여 처리합니다. 소프트웨어 업데이트 패키지는 주로 파일 이름, 리소스 업데이트 패키지는 주로 GitHub 리소스 저장소 zip 여부와 내부 version.json 파싱입니다.

  • 소프트웨어 업데이트 패키지(전체 / OTA) 드래그: v6.8.0-beta.2부터 지원.
  • 리소스 업데이트 패키지 드래그: v6.16.5부터 지원.

팁

GitHub Releases에서 다운로드한 패키지만 지원됩니다. MirrorChyan의 업데이트 패키지는 형식이 다르며, 자동 업데이트 전용이므로 드래그를 지원하지 않습니다.

소프트웨어 업데이트 패키지(전체 패키지 / OTA 증분 패키지)

  • GitHub Releases에서 해당 업데이트 패키지를 다운로드합니다. 파일 이름 형식은 변경하지 마세요:
    • 전체 패키지: MAA-<버전>-win-<아키텍처>.zip, 예: MAA-v5.20.0-win-x64.zip.
    • OTA 증분 패키지: MAAComponent-OTA-<현재버전>_<목표버전>-win-<아키텍처>.zip. 소스 버전은 현재 버전과 일치해야 합니다.
  • 드래그 후 MAA는 자동으로 압축을 풀고 다음 재시작 시 업데이트를 적용합니다.
  • 전체 패키지 업데이트에는 수동 확인이 필요: 전체 패키지는 설치 디렉토리 내의 이전 파일을 정리합니다(config, data, debug, cache, achievement, background 등은 보존). MAA를 독립된 폴더에 설치하고 다른 파일과 섞지 마세요.

전체 패키지 업데이트 위험

MAA를 디스크 루트, 바탕 화면, 다운로드 디렉토리에 직접 배치하거나, 다른 프로그램/개인 파일과 같은 디렉토리 계층에 혼재시킨 경우, 전체 패키지 업데이트가 동일 계층의 파일을 잘못 삭제할 수 있습니다. 반드시 MAA를 독립된 폴더에 배치하고 업데이트 전에 수동 백업을 수행하세요.

드래그 업데이트를 사용하지 않는 기존 방식

MAA 버전이 낮아 드래그 업데이트를 지원하지 않는 경우(v6.8.0-beta.2 이전), 전체 패키지를 새 폴더에 압축 해제한 후 이전 디렉토리의 config와 data 폴더를 복사하여 데이터를 보존할 수 있습니다. ⚠️ 이전 폴더에 직접 덮어쓰지 마세요. 잘못된 조작으로 리소스가 손상될 수 있습니다.

리소스 업데이트 패키지

  • GitHub에서 리소스 저장소의 zip 패키지를 다운로드합니다(GitHub 직접 다운로드 디렉터리 구조를 유지, 예: MaaResource-main/resource/... 포함).
  • 드래그 후 MAA는 패키지 내 version.json을 파싱하여 리소스 버전을 판단하고(현재보다 오래된 패키지는 가져오지 않음), resource 디렉토리에 압축 해제·병합한 뒤 자동으로 다시 로드합니다.
  • 리소스 패키지는 증분 콘텐츠이며, 기존 리소스 파일은 삭제되지 않습니다.
  • 드래그를 사용하지 않는 경우, 수동으로 압축을 풀고 resource 폴더를 직접 덮어쓸 수도 있습니다(⚠️ 증분 콘텐츠이므로 원래 폴더를 삭제하지 마세요).

지원되지 않는 패키지

드래그한 파일이 위의 어떤 업데이트 패키지도 아닌 경우(소프트웨어 패키지 파일 이름 불일치, 리소스 패키지가 GitHub zip 구조가 아님, 버전 불일치 등), MAA는 인식할 수 없다는 알림을 표시합니다.

패키지 내용은 완전히 검증되지 않습니다

  • 소프트웨어 업데이트 패키지(전체 / OTA): 주로 파일 이름으로 매칭하며, 압축 패키지 안이 실제 해당 아키텍처·버전인지는 검증하지 않습니다. 수동으로 이름을 바꾼 경우(예: arm64 → x64) 그대로 압축을 풀어 잘못된 버전이 설치될 수 있습니다. 원래 파일 이름을 변경하지 마세요.
  • 리소스 업데이트 패키지: GitHub 직접 다운로드 zip 구조인지와 version.json 파싱만 확인하며, 다른 리소스 파일의 완전성·정확성은 일일이 검증하지 않습니다. 일부 파일이 없어도 가져올 수 있습니다. :::

참고

  • UI에서 작업 순서를 변경할 수 있습니다. 인프라에서도 이동 순서를 변경할 수 있습니다.
  • 거의 모든 구성 변경은 자동으로 저장됩니다. *, (only once) 및 우클릭으로 반 선택하는 옵션은 예외입니다.
  • 모든 클릭 이벤트는 해당 지역 내에서 랜덤하게 발생하며, 포아송 분포를 따릅니다. (중심 부근에서 높은 확률, 주변에서 낮은 확률)
  • C++로 개발되었으며, 핵심 알고리즘은 CPU 및 메모리 사용량을 최소화하기 위해 다단계 캐시를 지원합니다.
  • 소프트웨어는 자동 업데이트를 지원합니다 ✿✿ ヽ(°▽°)ノ ✿ 베타 테스터들은 더 빠르고 덜 버그가 있는 베타 버전을 시도할 수 있습니다 (아마도).
  • 자동 업데이트에 실패한 경우 OTA(Over-The-Air) 패키지를 수동으로 다운로드하여 ZIP 파일을 동일한 디렉토리에 넣으면 자동으로 업데이트가 시작됩니다.
  • Windows 버전에서는 MAA 폴더의 config 폴더에 모든 설정이 기록됩니다. 새로운 완전한 패키지를 다운로드한 경우 이 폴더를 새로운 MAA 폴더로 복사할 수 있습니다.
