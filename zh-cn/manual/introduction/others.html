UI 专属功能

本页多数功能由 UI 层实现，详见新手上路中的说明。

GPU 加速推理

使用 DirectML 调用 GPU 进行识别推理加速PR，可通过少量的 GPU 占用降低大量的 CPU 占用，推荐启用。

经测试，部分显卡因缺少功能或性能较低，在使用本功能时会出现识别问题。MAA 已内置了部分 GPU 黑名单PR1PR2，若列表外的显卡在启用本功能后也出现识别问题，请发 Issue。

仅一次

主界面和设置中的配置更改通常会自动保存，但以下几种会在 MAA 重启后重置。

  • 标有 * 号的选项
  • 标有 （仅一次） 的选项
  • 通过右键单击复选框得到的半选开关

许多复选框支持右键单击进行半选（仅一次生效），MAA 重启后重置。常见的应用场景包括：

  • 主任务列表：右键勾选某个任务为半选状态，本次运行会执行该任务，但重启后恢复原状。默认右键为「仅一次生效」，可在 设置 - 界面设置 - 反转主任务右键单击效果 中切换为「仅一次跳过」（即右键半选的任务本次不执行）。
  • 战斗设置：使用药剂、使用源石 等选项右键半选后仅本次生效。

启动时自动切换配置

MAA 支持通过启动参数自动切换配置，在 MAA 进程名后附加 --config <配置名> 即可。例子：./MAA/MAA.exe --config 官服。

部分符号需要转义，参考 Json。例子：在配置名为 "官服" 时，参数应为 --config \"官服\"。

开始前/结束后脚本

v4.13.0 后支持设置开始前/结束后脚本，可在任务前后自动执行批处理文件。输入框内需填写批处理文件即 *.bat 的绝对或相对路径。

配置迁移

在 Windows 版本中，MAA 的所有配置都存放在 config 文件夹里。迁移此文件夹即可迁移 MAA 的所有设置。

定时执行

在 设置 - 定时执行 中可设置最多 8 组定时任务。每组包含启用开关、时间（时:分）和对应的配置。

  • 定时时间到达后，MAA 会自动连接模拟器并开始执行当前配置中勾选的任务。
  • 每个定时项的复选框支持右键半选（仅一次），即只在本次生效，MAA 重启后重置。

强制定时启动

勾选后会停止当前正在运行的任务，重启游戏并开始新任务。适用于应对游戏每日 04:00（服务器当地时间）的闪断更新——在闪断时间后强制重启游戏并重新执行任务，确保任务不会因闪断而卡住。

如需闪断更新后自动重连并继续任务，请同时启用 开始唤醒 任务。

自定义配置选择

勾选后，每个定时项可以指定不同的配置。MAA 会在定时触发前两分钟重启并切换到对应配置，再开始执行任务。

更新

MAA 的更新分为两种内容：

  • 软件版本：主程序的界面和功能更新。
  • 资源版本：素材数据更新，包含新关卡地图、掉落物图标、公招干员标签等。软件版本发布时通常已包含当时的最新资源。

导航热更

另有一种「导航热更」，会自动触发，用于更新主界面提示与活动关卡入口。成功后右上角会显示提示。

更新渠道

可在 设置 - 更新设置 中切换更新渠道：

  • 正式版：Bug 更少，新功能新主题支持更慢。新功能可能需要数周后才会支持。
  • 公测版：可能存在少量 Bug，新功能新主题支持更快。
  • 内测版：包含不稳定功能，仅供测试。请勿在其他地方讨论内测版问题。

提示

若界面提示版本过低且最低需求版本为公测版，但检测已是最新版本，说明该功能目前仅在公测版中提供，需等待正式版发布或切换至公测版获取。

自动更新

在 设置 - 更新设置 中可选择更新源：

更新源说明
海外源（GitHub）软件版本从 GitHub 拉取；资源版本由 Mirror酱 提供免费的更新检测，可手动点击 资源更新 从 GitHub 下载。
Mirror酱填写 CDK 后支持软件与资源的自动更新，优先通过高速 CDN 下载，更稳定快速。

可在更新设置中开启或关闭以下选项：

  • 启动时检查更新
  • 定时检查更新（对应服务器当地时间 04:00 / 22:00，即游戏内每日重置时间和理智完全恢复时间）
  • 自动下载更新包：关闭后仅通过通知提示，可自行下载更新包后拖入 MAA 完成更新（见下方手动更新）。
  • 自动安装更新包

资源更新在任务期间检测到时，会在系统空闲时自动加载，于下次任务生效。

手动更新

如果自动下载失败或网络不佳，可以手动下载更新包，然后直接将 .zip 压缩包拖入 MAA 主窗口即可完成更新。MAA 会识别包类型并处理：软件更新包主要看文件名；资源更新包主要识别是否为 GitHub 资源仓库 zip，并解析其中的 version.json。

  • 拖入软件更新包（完整包 / OTA）：v6.8.0-beta.2 起支持。
  • 拖入资源更新包：v6.16.5 起支持。

提示

仅支持从 GitHub Releases 下载的包。Mirror酱 的更新包格式不同，且为自动更新专用，不支持拖入。

软件更新包（完整包 / OTA 增量包）

  • 从 GitHub Releases 下载对应的更新包，文件名格式需保持不变：
    • 完整包：MAA-<版本号>-win-<架构>.zip，如 MAA-v5.20.0-win-x64.zip。
    • OTA 增量包：MAAComponent-OTA-<当前版本>_<目标版本>-win-<架构>.zip，源版本必须与当前版本一致。
  • 拖入后，MAA 会自动解压并在下次重启时应用更新。
  • 完整包更新需要手动确认：完整包会清理安装目录下的旧文件（保留 config、data、debug、cache、achievement、background 等），请确保 MAA 安装在独立文件夹中，不要与其他文件混放。

完整包更新风险

如果你把 MAA 直接放在磁盘根目录、桌面、下载目录，或与其他程序/个人文件混放在同一层级，完整包更新可能会误删同级文件。请务必将 MAA 放在独立文件夹内，并在更新前手动备份。

不使用拖入更新的传统方式

如果 MAA 版本过低不支持拖入更新（v6.8.0-beta.2 之前），可解压完整包至新文件夹，再复制旧目录的 config 和 data 文件夹以保留数据。⚠️ 请勿直接覆盖旧文件夹，错误操作可能导致资源损坏。

资源更新包

  • 从 GitHub 下载资源仓库的 zip 包（保持 GitHub 直接下载的目录结构，例如含 MaaResource-main/resource/...）。
  • 拖入后，MAA 会解析包内 version.json 判断资源版本（不会导入比当前更旧的包），再解压合并到 resource 目录并自动重载。
  • 资源包为增量内容，不会删除原有资源文件。
  • 不使用拖入时，也可手动解压后直接覆盖 resource 文件夹（⚠️ 增量内容，请勿删除原文件夹）。

不支持的包

如果拖入的文件不是上述任何一种更新包（如软件包文件名不匹配、资源包不是 GitHub zip 结构、版本不匹配等），MAA 会弹出提示告知无法识别。

不会完整校验包内容

  • 软件更新包（完整包 / OTA）：主要依据文件名匹配，不会校验压缩包内是否真为对应架构或版本。若手动改名（例如将 arm64 包改名为 x64），仍可能照常解压并装错版本。请勿修改原始文件名。
  • 资源更新包：只检查是否为 GitHub 直接下载的 zip 结构，并解析 version.json；不会逐一校验包内其他资源文件是否齐全或正确。缺少部分文件时仍可能导入。 :::

其他说明

  • 首页左侧任务可以拖动改变顺序，基建换班设置中设施顺序同理。
  • 所有点击操作，都是点击按钮内随机位置，并模拟泊松分布（按钮中心的点击概率最高，距离中心越远，点击概率越低）。
  • 底层算法纯 C++ 开发，并设计了多重缓存技术，最大限度降低 CPU 和内存占用。
  • 软件支持自动更新 ✿✿ ヽ(°▽°)ノ ✿ ，推荐非杠精的同学使用公测版，一般来说更新快且 bug 少。（什么 MIUI (╯‵□′)╯︵┻━┻
  • 如果新版本自动下载失败，可手动下载 OTA 压缩包后直接放到 MAA 目录下，会自动更新的。
