# 任务、调度和游戏识别失败

先把问题分为没有启动任务、启动前跳过、任务已下发但运行出错、任务按配置结束。｢任务出错｣ 本身只能定位到某条任务链，需看前序日志或现场画面。

| 用户描述 | 优先核对与验证 |
| --- | --- |
| 点 ｢Link Start!｣ 没跑 | 看是否仍在加载内核、资源损坏或等待重启。确认当前配置和任务勾选，临时半选是否是跳过模式。对比是否有 `Start Task Chain`，若已尝试连接但未成功，转 [连接与控制](connection-and-control.md)。 |
| ｢任务跳过｣、｢序列化失败｣、｢添加任务失败｣ | 跳过可能是周计划、库存、触发间隔或活动条件。序列化/添加失败在 GUI 下发阶段，先看具体任务与异常。v6.21.3 若有序列化失败，会中止本轮启动。只有看到运行的 task ID 和回调后才按游戏内流程排查。 |
| 理智作战进错关、找不到关卡或开不了代理 | 看 `GetFightStage` 的候选和最终选择。｢当前/上次｣ 会尝试当前定位或上次作战；备用关卡选开放的候选，开不了代理时未必会再换下一项。确认区服、活动期、资源日期、手输关卡编号和难度、游戏内代理是否已解锁。把同一关手动停在代理画面测试。 |
| 理智作战打少了、停止或消耗药剂/源石 | 按停止时的战斗日志核对次数、掉落目标、库存目标与理智预算；固定倍率只执行不超次数的整组，AUTO 会调整。检查临期药与使用源石选项。要求 ｢不碎石｣ 时先确认源石开关处于关闭。 |
| 库存保持没刷、识别后仍少刷 | 检查任务日志是否写库存为空、达标、活动跳过或理智不足。预检使用识别前缓存，识别后才发现短缺的计划不会插回当前队列。若日志显示 ｢预检时已跳过的计划无法在运行中添加｣，先单独同步仓库再重新运行。另查 ｢仅执行第一个库存不足的计划｣，其后的条目可能尚未检查。仓库识别结果为空时旧缓存可能保留，需核对最后同步结果。 |
| 更新数据没有执行或数据看似过期 | 看干员/仓库子项是否勾选，检查每次/每天/每周的触发间隔与最后同步时间。一图流干员识别使用远端快照，核对是否已在一图流上传新数据。不要把任务 ｢更新数据｣ 当作 ｢资源更新｣。 |
| 信用没赚到或会客室线索被取下 | 核对 OF-1 解锁和 ｢当前/上次｣ 冲突，区分好友访问、购物和基建里的会客室操作。线索不足以开交流时可能主动取下以避免容量阻塞。若疑似取下后错误停止，比较操作前、点击后和终态的截图与资源任务。 |
| 抄作业/肉鸽部署不动、识别错误 | 先核对正常编队、悖论模拟、保全、多作业的起始画面。检查作业是否匹配关卡及干员练度，取消相关干员的特别关注。肉鸽确认主题、当前探索状态与策略；再看帧率、触控、截图、异形屏适配（设为 0）。开启划火柴模式或 GPU 加速推理时可分别关闭做同场景对照。 |
| 版本更新后在游戏新界面识别失败 | 看现场图和资源日期。客户端区服、主界面主题和活动入口都会影响模板或 OCR，先用日间主题复现并核对对应版本适配。游戏登录错误与设备 ADB 断开分别取证。 |
| 定时没跑或跑错配置 | 检查定时启用、Windows 本机时钟、运行时是否已有任务、是否选了目标配置。自定义配置在触发前两分钟切换，查 `Scheduled configuration change`、`Scheduled start` 和配置不匹配提示。若同时使用作战周计划，再按区服的游戏日判断该任务是否会跳过。 |
| 睡眠后漏跑或模拟器没启动 | 区分普通定时与 Windows 唤醒启动。若启用了唤醒，查 Windows 任务计划、供电状态、设备是否支持唤醒以及 MAA 是否提前启动。唤醒启动会跳过常规启动自动运行项。定时开模拟器需配置启动路径和 ｢ADB 连接失败时尝试启动模拟器｣。 |
| 结束没退出或没关机 | 确认 ｢完成后｣ 的实际设置、是否仅当次、是否启用 ｢任务出错时跳过｣ 或 ｢无其他 MAA 时｣，再查对应动作失败日志。系统休眠看 Windows 电源设置。 |

任务问题仍能复现时，保留失败画面和同一次的 GUI/Core 日志，按 [证据索引](evidence.md) 判断是预期条件还是实际故障。
