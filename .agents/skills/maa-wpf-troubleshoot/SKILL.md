# MAA Windows WPF 故障排查

按最早异常的阶段选择一份参考。用户只给一句现象时，可以先提供能区分原因的低成本检查，再询问最能缩小范围的证据。

| 现象 | 参考 |
| --- | --- |
| 打不开、喜报或悲报、DLL、安装文件缺失、配置恢复、更新循环或半更新 | [启动与更新](references/startup-and-updates.md) |
| 找不到模拟器、ADB 连接失败、设备离线、分辨率、截图为空或慢、连接后无操作 | [连接与控制](references/connection-and-control.md) |
| 点击开始没执行、任务跳过或出错、关卡导航、库存偏差、战斗识别、定时 | [任务与调度](references/task-failures.md) |
| 有截图、日志、报告包、公开 Issue，或自查后仍可复现 | [收集与判读证据](references/evidence.md) |

## 排查顺序

1. 确认是 Windows WPF 版，记录复现时间及界面、核心、资源版本。按需收集模拟器名称和版本、客户端区服、连接配置、触控模式、所选任务和关卡。分开看第一次失败、自动重试和最终结果。
2. 区分安装与启动、设备连接、截图、输入、导航与识别、任务配置和游戏状态。先给能定位问题的检查，例如截图测试、核对设备列表、让同一任务在预期画面手动复现。只在证据指向时才建议修改设置或恢复安装。
3. 基线为正式版 v6.21.3（`561fca9d0ab37e07256b6514fe970847f0fcafa6`）。先以用户实际版本、资源和日志为准。新版本已修复时核对合入提交是否在用户所用发布 tag 中，避免用开发分支或单个历史 Issue 推断普遍根因。界面名称以对应版本的本地化与 XAML 为准。
4. 回复包括现象或判断、可操作的下一步和成功判据。未定位时说明缺少的证据。日志只摘必要的脱敏行。凭据由用户在本机检查，只分享必要且已脱敏的证据。已有公开 Issue 需要逐行取证时，可结合仓库的 `maa-issue-log-analysis`。
